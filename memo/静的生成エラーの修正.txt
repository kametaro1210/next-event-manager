
============================================================================
Next.js静的生成エラーの修正
============================================================================
----------------------------------------------------------------------------
問題と修正理由
----------------------------------------------------------------------------
本番ビルド時、/auth/[path]の生成中に、リクエスト時にしか分からない情報を
読み取ろうとしてエラーになりました。ビルド中は、アクセスする人やCookieが
まだ分からないためです。

動的な処理をSuspense内に分け、getSession()のようにライブラリ内部でCookieを
読む処理はconnection()の後に実行することで、ビルドとリクエスト時の処理を
分けています。これをしないと本番ビルドやデプロイに失敗する可能性があります。

----------------------------------------------------------------------------
他のNext.jsプロジェクトでの直し方
----------------------------------------------------------------------------

Next.jsのバージョンや設定で必要な対応が変わるため、まず対象プロジェクトの
package.jsonとnext.config.*を確認します。以下はCache Componentsを使う場合の
手順です。

1. npm run buildを実行し、エラーが出たページと、ビルド時に使えないデータを
   エラーメッセージから確認します。
2. そのデータを読む場所を探します。ページ内のcookies()、headers()、
   paramsなどのほか、getSession()などライブラリの中で読む場合もあります。
3. 読み取り処理をSuspenseの内側に置きます。Suspenseは、処理中に代わりに
   表示するUIを指定するものです。
4. Next.jsがデータの読み取りを検知できない場合だけ、その処理より前に
   await connection()を置きます。たとえば、ライブラリ内部でCookieを読む
   getSession()が該当します。cookies()などNext.jsのリクエストAPIをすでに
   使っている場合は、通常connection()を追加しません。
5. npm run buildをもう一度実行し、ビルドが成功することを確認します。

connection()はログイン確認の機能ではありません。また、すべてのページに
追加するものでもありません。後続の処理をリクエスト時に実行させるため、
本来ビルド時に作れるページまで毎回サーバーで作られ、表示が遅くなる場合が
あります。エラーが示す処理にだけ追加してください。

Suspenseとconnection()の役割は別です。Suspenseは処理中の表示を担当し、
connection()は後続の処理をリクエスト時まで遅らせます。

----------------------------------------------------------------------------
このプロジェクトでの例
----------------------------------------------------------------------------

- app/dashboard/page.tsxはgetSession()が内部でCookieを読むため、
  その前にconnection()を置いています。
- app/account/[path]/page.tsxはページ内でgetSession()を呼ばず、
  AccountViewを表示します。セッション取得は認証UI側が行うため、
  このページにconnection()はありません。
- app/auth/[path]/page.tsxとapp/invite/[token]/page.tsxは、URLの値を
  Suspense内で読み取るためconnection()を追加していません。

----------------------------------------------------------------------------
Suspenseの表示
----------------------------------------------------------------------------

app/events/[eventId]/page.tsxでは、EventDetailsPageContentの処理中に
Suspenseが待機します。2秒を超えて待つ場合だけ、DelayedSpinnerを表示します。

----------------------------------------------------------------------------
変更対象ファイル
----------------------------------------------------------------------------

- app/auth/[path]/page.tsx：pathと認証画面をSuspense内に配置。
- app/account/[path]/page.tsx：pathをSuspense内に配置。
- app/dashboard/page.tsx：getSession()の前にconnection()を追加。
- app/events/[eventId]/page.tsx：pathとgetSession()をSuspense内で処理。
- app/events/[eventId]/edit/page.tsx：pathとgetSession()をSuspense内で処理。
- app/invite/[token]/page.tsx：URL情報をSuspense内で処理。
- components/delayed-spinner.tsx：2秒後に表示する共通スピナー。
